# 方法研究接入研究周期的架构评审

本次从课题负责人、执行者和交接者的入口检查公开包。设计目标是让研究问题、方法条件、可重建的计算与结论依据连得起来。前期综合与复现已有专门入口；方法开发缺少的是从“我要重新构造这个方法”走到第一次可裁决的设计选择。RTMScore 回溯也受到派发方式影响：首次任务明确要求先跑作者示例和权重，后来研究者澄清目标，才比较自行构造的候选方法。因此这个案例同时暴露了委托和入口的问题。[设计愿景](../../core/docs/design/01-design-vision.md) · [RTMScore 论文](https://doi.org/10.1021/acs.jmedchem.2c00991)

## 四种研究交付怎样共用现行架构

| 交付 | 决定与所用证据 | 在原框架中的位置 |
|---|---|---|
| 前期综合 | 研究者综合测量、方法和分歧，可以独立交付综述；需要改变方向时说明选择依据 | [研究准备](../../core/docs/methods/guides/research-preparation.md)已有来源账本、证据图和候选问题 |
| 已有结论复现 | 对位作者输入、实现、评价单位与分母，配对核对可改变判断的条件 | [研究接续](../../core/docs/methods/guides/task-continuity.md)连接计划、运行和交付；[配对比较](../../core/docs/methods/guides/function-and-utility-validation.md#解释两次计算的差值)检验声明的一致性 |
| 方法开发 | 理论层提出尚待实测的选择，应用层确定单位、参照与改选条件，执行层构造候选并比较，结果可以支持保留原方法、转向或暂缓 | [开发入口](../../core/docs/methods/guides/research-guidance-cycle.md#从已有问题重新开发方法)复用原有的问题、候选、选择、运行与评价记录。历史技术边界、曾见过的目标实现及设计来源由研究者说明 |
| 独立评阅 | 保留被审版本，逐项判断测量、比较、主张及未决项。方法研究还要回看备选方案何时进入研究、哪项结果改变过选择 | [修订与接受](../../core/docs/methods/guides/revision-responses-and-acceptance.md)仍按选定回应路线验收 |

这些接口能表达四项工作；记录齐备之后，还要检验代理实际选择了什么、数据是否区分路线，以及读者是否能沿证据讲清判断。对方法开发的首交，采用简单方法、发现已有方案更好或留下确实无法裁决的分歧，都可以是有用的科研结果。

## 原有结构评议的复核

[结构评议](https://github.com/vvcchh0/BioInformaticsHarness/issues/8)来自研究路径视图的开发。这里沿它的十二条建议核查实际派发的基线包（版本身份见[试验记录](../../machine/history/method-research-20261119.json)）；下表的原文、清单与后文的段落抽样均按该版本计数。视图已有按具体周期绑定账本、按实际引用标阶段的修复；原作者当时列出的重复处与现状应分别计数。[视图 PR](https://github.com/vvcchh0/BioInformaticsHarness/pull/7) · [维护者的处理顺序](https://github.com/vvcchh0/BioInformaticsHarness/issues/8#issuecomment-6555622753)

| 原议题 | 现状及处理决定 |
|---|---|
| 1–4 修订、账本、讨论与活动周期的关联 | 视图会递归扫描并排列版本。两个后继共享前版时，末尾显示者未必是负责人选择的活动分支。两份记录相互前指时，旧检查器逐条查前版仍可通过。在单独变更中验证前版链、支持多个修订对象与明确的活动入口；旧记录缺少归属时显示未知 |
| 5 阶段与出口词表 | 视图已复用检查器的阶段顺序。原页面却把创建新版本列作证据修订的出口，漏了补读、回到讨论或计划。本试验将页面可显示的出口接回机器设计。其余阶段及意图常量的统一可分别核对既有调用者 |
| 6 下一动作的归属 | 课题负责人记录的下一步、检查器指出的待办、证据图提出的方向分别有用。本分支修复一种会误导接手者的组合：方向仍待人选，且材料损坏或缺失。先显示可修复的材料问题，保留方向关口，并把实际跳过的阶段标为未经检查 |
| 7–8 记录格式与两类工具 | 准备和执行工具消费研究工件，验证工具检查记录关系及回应。名字相近的命令不一定接受相同输入。新格式采用明确的字段约定，旧格式优先通过兼容读取连接；长期可从高频记录建立对照，避免整体改名迁移 |
| 9–11 换行、历史原文、双层清单 | 工作树有混合换行并按字节验收。改动应保留未编辑行。117 份注记保存原文，只有 20 份与现行对应文件逐字节相同；按本地可达 Git 历史和同一路径匹配，有 5 份原文未命中。独立 core 与整库清单有 302 条共同路径。先验证离线分发的恢复和两个发布入口，再评估合并、精简或自动生成 |
| 12 路径检查 | 读取既有输入、创建报告、搬移分发包各有不同的文件存在性与链接语义。后续应先用各调用者的回归示例约束行为，再抽取共有操作 |

在虚构的两版研究示例上，视图构出 38 个节点和 68 条边，呈现的缺口数为零。对同目录的修订记录运行专门检查器，仍有待决事项，包括计划中的工作与尚缺的评阅回执。若下一轮将视图用于交接，应给读者同时呈现当前活动分支、结构检查范围和具体评阅裁定，再用真实课题观察能否定位下一项义务。[视图与示例](../../core/examples/research-support/study-view/README.md)

## 防御性措辞是否抑制行动

抽查 17 份入口和常用指南，在 243 个达到长度门槛的自然段中，跨文档逐字重复的段落数为零。这个口径无法检测近义重复。更有操作后果的是图中原先唯一通往方向选择的人工讨论路径，以及示例模板预置的待人工选择。对已经委托的内部技术选择，检查器原本就能接受有来源的授权；新入口、图和模板说明现在让读者看得见这条路径。需要用户决定研究用途或追加资源时，仍由人选择。

在同一道模拟荧光板校正题上，两名相同配置、独立上下文的代理分别从基线和试验入口开始。两者均主动完成首次计算，对照原始标准比与扣空白后的两点校正，得到相同的三个相对值。试验稿还明确了何时改用多点校准。这个小题未显示自主启动能力的差异，且不能单独估算措辞、模板或派发方式的影响。全面改写前，更有价值的是让多个独立会话在较难的历史问题上提出并放弃候选，交叉比较入口文本与派发指令，并让独立读者盲评设计理由。[本轮机器记录](../../machine/history/method-research-20261119.json)

**本轮决定**是在本地分支复用现有架构试行方法开发；优先纠正能导致下一步走错的文案、输出与视图。全面替换术语、删历史原文或合并记录格式，都需要各自的兼容和恢复证据。
