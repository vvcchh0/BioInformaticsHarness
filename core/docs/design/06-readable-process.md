# 面向读者的研究过程说明

日期：2026-09-29。完整过程说明帮助没有参与实验的人理解研究选择和结论。

## 写作顺序

从研究问题与动机开始，说明为何选择当前方法，再依次介绍关键输入、划分、操作、调整、失败和结果。结尾说明结果支持什么、尚有哪些问题，以及接手者可以采取的下一步。

每个重要步骤要让读者跟上：它在解决什么问题，为什么采用这个操作，观察怎样改变了判断，接下来因此怎么走。这是组织思路，不要求每段填四个栏目。先交代读者理解操作所需的对象和术语，再用目的、比较与结果之间的关系连接句子。叙述保持实际行动的先后与依据，不为流畅补造当时的动机或因果。

图表应帮助读者看清对象和操作之间的关系。流程图、序列图或前后对照都可以；实际观测、计算预测和人工示意要用合适的标题或图注区分。读者需要重建具体结果时，给出与图表对应的脚本和输入材料入口。

## 选择内容详略

过程说明覆盖会影响研究理解的决定、结果和外部依赖。重复日志与日常工具调用放在可检索记录中；正文用清楚的链接指向它们。这样读者既能快速理解，也能在需要时查看细节。

可读过程既能作为研究交付物，也能帮助团队内部交接。每项关键结论都应能回到测量和来源，未完成的步骤则说明它会影响哪项后续判断。

交互视图优先引用已有的人读说明段落，再提供数值、参数和原件入口。共享背景可以集中解释；条件放在会改变理解和选择的位置，不在每张卡片重复审计摘录。来源、编号和范围检查继续进行。

可读性验收问：读者能否在不打开JSON、也没有参与过实验的情况下，说清这一步为什么做、做了什么、结果为何重要？请读者用自己的话复述，并指出影响下一步的条件。代理试读可检查解释缺口，实际人的理解状态按真实反馈记录，不由文件齐备或代理通过代替。
